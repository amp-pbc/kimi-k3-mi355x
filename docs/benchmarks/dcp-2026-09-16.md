# Single-node AITER DCP test, 2026-09-16

TP8/DCP8 ran successfully on one 8×MI355X node using the pinned upstream
ROCm vLLM 0.29.0 image. It passed the same six correctness smoke checks as
DCP1 and increased reported KV capacity by about 4×. It did not produce a
material throughput improvement on this synthetic input-heavy workload.

## Environment and method

- Image: `vllm/vllm-openai-rocm:v0.29.0@sha256:e5e47f6aaab675c252c381f0dac237b31b10d87bb74d092b07fb4065efd7f5a1`.
- Observed versions: vLLM `0.29.0+rocm723`, `amd-aiter 0.1.19`, PyTorch
  `2.12.0+git6bbd260`, HIP `7.2.53211`, Transformers `5.16.1`.
- Full MXFP4 Kimi-K3 checkpoint at revision
  `f831ab66814297da540d832a5235f8e904f29d06`, reused from local NVMe after
  checking download-revision metadata and file sizes against shared storage.
- Same pod, node, image, model, seven environment variables and serving
  arguments for both arms; only DCP changed from 1 to 8. TP8, 32,768-token
  context cap, BF16/auto KV, 4,096 batched tokens, 128 maximum sequences,
  GPU memory utilization 0.95. No speculative decoding.
- Selected backend: `ROCM_AITER_MLA`. DCP8 logs also showed AITER native
  MLA decode kernels with LSE support. See the [launch configuration](../10-decode-context-parallel.md#pinned-single-node-configuration).
- Separate single-endpoint Python/httpx driver in the serving container,
  using loopback `/v1/completions` with pretokenized synthetic inputs. This
  isolates engine execution and excludes text tokenization, chat templating,
  external networking, routing and PD transfer from the performance numbers.
- Exact input lengths of 1,024 or 28,672 tokens, 128 generated tokens forced
  with `ignore_eos=true`, temperature zero. Identical prompt-token hashes
  across arms; unique leading content per request and cohort. Measured
  prefix-cache hits were zero. These are synthetic records, not customer or
  OpenRouter traffic.
- One outstanding request per concurrency slot, fixed request counts, no
  retries, complete draining between steps. Each point had a separate warm-up
  followed by two measured cohorts. Startup/compilation and warm-ups excluded.
- Closed-loop batch throughput: completed tokens divided by elapsed time
  through the last completion. DCP1 ran first, then DCP8. Repeats were within
  each arm; this was not an alternating-order statistical performance study.

## Results

All throughput values are **per node (eight GPUs)**. Each row pools the two
cohorts by dividing their combined completed tokens by combined elapsed time.

| Input tokens | Concurrency | Requests per arm | DCP1 output tok/s | DCP8 output tok/s | Change |
|---:|---:|---:|---:|---:|---:|
| 1,024 | 1 | 32 | 50.60 | 47.71 | -5.7% |
| 1,024 | 8 | 64 | 294.78 | 267.84 | -9.1% |
| 28,672 | 8 | 64 | 53.71 | 53.96 | +0.5% |
| 28,672 | 32 | 128 | 60.07 | 59.54 | -0.9% |
| 28,672 | 96 | 384 | 60.93 | 60.45 | -0.8% |

For the long-input rows, input tok/s is output tok/s × 224 because every
request had 28,672 input and 128 output tokens, with zero measured cache hits.

| Input tokens | Concurrency | DCP1 TTFT p50 / p99, seconds | DCP8 TTFT p50 / p99, seconds |
|---:|---:|---:|---:|
| 1,024 | 1 | 0.25 / 0.26 | 0.25 / 0.26 |
| 1,024 | 8 | 0.67 / 0.82 | 0.69 / 0.87 |
| 28,672 | 8 | 2.94 / 16.49 | 2.99 / 16.78 |
| 28,672 | 32 | 31.86 / 66.68 | 32.10 / 67.25 |
| 28,672 | 96 | 165.15 / 198.07 | 166.39 / 199.68 |

Reported GPU KV capacity was **2,162,688 tokens (DCP1)** versus
**8,617,984 tokens (DCP8)**, a **3.985×** increase. vLLM reported theoretical
32K-context concurrency of 66× versus 263×. The latter is a memory-capacity
estimate, not measured concurrency or throughput; the serving limit remained
128 sequences.

Validation receipts:

- 672/672 measured requests per arm, **1,344/1,344 total**, plus 145 successful
  warm-up requests per arm. Client usage matched engine request, prompt-token
  and generated-token counter deltas at every measured point.
- All six correctness smoke checks passed on both arms: addition, multiplication,
  sorting, long-context retrieval, reasoning output and automatic tool-call
  parsing. This is a smoke suite, not a comprehensive model-quality evaluation.
- No measured preemptions or prefix-cache hits; no container restarts or
  reported ROCm runtime faults during serving. Identical prompt hashes and
  serving arguments except DCP were checked after the run.
- Read-only metric sampling during the high-concurrency portion showed
  substantial KV-cache headroom and requests waiting. The workload did not
  establish a benefit from exhausting the larger DCP cache.

Both arms logged TCPStore/broken-pipe and shared-memory cleanup warnings during
the harness's deliberate process-group SIGTERM teardown, after requests had
drained. DCP8 took about 46 seconds to exit. These warnings occurred after the
measurement windows; this experiment does not establish production graceful
shutdown behavior.

## Interpretation and limits

This verifies basic AITER MLA DCP on the official image without a vLLM/AITER
source patch. More cache capacity did not materially improve throughput on these
input-heavy, short-output requests. Raising concurrency mostly increased
queueing and latency; the high-concurrency rows are not low-latency capacity
or production SLO claims.

A workload with longer outputs, larger active contexts, different arrival
patterns or cache reuse may behave differently. The GB300 throughput claim
cannot be confirmed or rejected for its original workload from these tests.
Obtain that workload and repeat with alternating arm order before claiming a
general speedup.

This test did not cover the multi-node Infera/Mooncake/DSpark runtime. It does
not validate substituting this official image into that recipe; see the
[PD upgrade requirements](../10-decode-context-parallel.md#upgrading-the-multi-node-pd--dspark-runbook).

The experiment used customer Kubernetes resources only. The owned test Job,
ConfigMap and CPU probe were removed after artifact collection. Shared model
storage was retained. Workload deletion does not independently establish
marketplace node release or billing cessation.
